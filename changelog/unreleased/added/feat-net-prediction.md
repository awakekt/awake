- **Client-side prediction and reconciliation for any networked game.** The new `awake:net:prediction` module keeps a `PredictionHistory` of the pose each input left a locally predicted entity at, and a pure `reconcile` compares a server snapshot with the pose kept for the input it acknowledged, not the pose drawn now. It answers with a `Correction`: `Blend` a small drift into movement, `Shift` by a real one keeping the steps the server hasn't acknowledged, `Snap` for a far drift, a lost history or a game's own `SnapReason` through `ReconcileRules`, or `Wait` to ease the entity to a stop once the server has heard none of its inputs for as long as it guesses them on (by default its 0.5 s guess window plus a 0.25 s ease), timed from the newest input it heard rather than its acknowledgement, which counts guessed ticks. A snapshot corrects only when its acknowledgement is fresh and the server guessed few of its ticks. `ReconcileConfig` holds the thresholds, and `PredictedEntity` applies a correction to a plain pose with a shift drawn as a short glide through `core.math`'s `ErrorOffset`. It depends on `awake:core:math` alone (#1290).
