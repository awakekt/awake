- **`rememberStore` and `rememberReducerStore` can run their store under a parent scope, and close remembered stores (#1320).** New overloads take a `parent: CoroutineScope` first, normally the app's `AppCoroutineScope`, and run the store on `parent.childStoreScope()`: its uncaught failures reach the parent's handler and cancelling the parent cancels it. Every remembered store, with or without a parent, is now closed when the composition forgets it (its key or parent changed, its call stopped being made, or its node left the tree), so its coroutines no longer outlive the UI that made it.
