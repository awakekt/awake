- **Published projects load from content bundles, one request per bundle instead of one per file.** A content bundle (`ContentBundleFormat`, `.awkb`) is a header and table of contents (key, offset, size and SHA-256 per member) followed by the members' bytes, stored and fetched by its own SHA-256. `ContentBundleWriter` packs a loose index's files into bundles grouped by folder (`ContentBundleGrouping.byFolder`), by a grouping of your own such as per scene, or into one group, filled to a size target (16 MiB by default); the same files always give byte-identical bundles, so a publish uploads only changed ones. The new `awake bundle <index> --output <dir>` command does it from the command line. The project index gains `formatVersion` 3: a `bundles` list, entries that name a bundle and an offset instead of a URL, and optional opaque ids (`ProjectPathIds`, a salted hash of each path) so the published index and bundles list no readable paths; version 2 indexes load exactly as before. `IndexedAssetSource` reads bundled entries transparently, through a plain fetch or a `TokenAuthorizedFetch`: the first read fetches the whole bundle once, checks the bundle and every member, and caches each member by its own SHA-256; concurrent reads share one fetch; `prefetch` downloads whole bundles; a damaged bundle fails naming each damaged member's path. An optional `rangeFetch` (or `IndexedAssetSource.open(..., rangeReads = true)` with the new `TokenAuthorizedFetch.fetchRange`, which sends a `Range` header with the token) reads one member alone. `IndexedAssetSource`'s constructor and `open` factories, and `ProjectIndex` and `ProjectIndexEntry`, gain trailing optional parameters, which changes their JVM signatures. The Content bundles guide covers choosing groups and sizes (#1032).
