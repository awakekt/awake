- **Plugins ship default text a game overrides, Compose UI reads the active table, and keys and buttons have names in the player's language.** `Strings.addSource(source, layer)` adds a layer of tables: the game's own (`StringLayer.Game`) win over a plugin's defaults (`Plugin`), which win over Core's built-in text (`BuiltIn`). Each locale's table is the layers merged key by key, and the locale comes before the layer, so a plugin's Korean shows for a Korean player while the game's English overrides the plugin's English. `removeSource` takes a layer away. The new `compose:localization` module gives Compose UI `LocalStrings`, `stringResource(key, args)`, `LocalInputLabels` and `ProvideStrings`; text shows a new locale on the frame after `setLocale`. `InputLabels` names keys, mouse buttons, controller buttons (`GamepadButton`, in a `ControllerLayout`), and the chords and bindings `core:input` describes (`binding(BindingDescription)`, `chord(InputChord)`, `bindings(ButtonAction)`), in the player's language and `ShortcutStyle` (`Ctrl+Shift+K` on Windows, `Control+Shift+Cmd+K` on Apple platforms), with built-in English, German, French and Spanish names that a game overrides through `input.*` keys. `core:localization` now depends on `core:input` through `api`.
