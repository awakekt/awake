- **Multiplatform message routing and client network feature DSL in `awake:net:api`.** `MessageRouter<C, M>` (`messageRouter { on<T> { ... } }`, `MessageRouter.from`, `MessageRouter.empty`) dispatches incoming packets by `KClass` in `O(1)` without per-packet allocation or central `when` branches, and `ClientNetFeature<C, M>` with `ClientNetFeatures<C, M>` (`clientNetFeature(id) { on<T> { ... }; flushOutbound { ... }; onConnected { ... }; onDisconnected { ... } }` and `clientNetFeatures { install(...) }`) let each client feature own its inbound handlers, outbound request pump and connection lifecycle hooks across desktop, mobile and `wasmJs`, rejecting duplicate feature IDs and colliding message routes at registration time. `awake:net:server-ktor`'s `MessageRouter` delegates to the shared router with unchanged binary compatibility (#1308).
