- **Localization: string tables per locale.** The new `awake:core:localization` module loads `strings/<locale>.json` tables through a project's `AssetSource`, one locale at a time and only when it is used, and `Strings.text(key, args)` looks a key up in the active locale, its parents (`pt-BR`, then `pt`) and the default locale. A missing key or locale shows the key or the default text and is logged once, never thrown. Text is ICU MessageFormat style: named `{placeholders}`, `plural` with Unicode CLDR rules for English, Spanish, Filipino, Korean, Japanese, Chinese, Russian, Arabic and a dozen more, `select`, and ICU apostrophe quoting. `strings.locale` is a `StateFlow`, `setLocale` switches at run time, and `systemLocale()` reads the device language on desktop, Android, iOS and the web. `LocaleFonts` and `Strings.loadFont` give a locale fallback fonts for scripts the UI font lacks, through the new `UiFonts.fallback` chain and `UiFont.hasGlyph` in `core:text`. The project-content index now covers `strings/`, and the engine showcase has a `localization` sample in English and Filipino.
