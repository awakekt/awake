- **Input actions take modifier chords, and a player's bindings are data that can be rebound at run time.** A `ButtonAction` now takes `chords` beside its keys and pointer buttons: a `KeyChord` such as Shift+1 or Ctrl+Alt+K, or a `GamepadChord`, a controller button pressed while a shoulder or trigger is held. Bindings on the same key resolve across every action: the chord whose modifiers were held when the key went down wins, the most specific first, and keeps the key until it is released, so Shift+1 does not also fire 1, and Ctrl+S bound to saving does not walk the player back on an S axis. A chord's `extraModifiers` says whether other held modifiers stop it (`Block`, the default) or not (`Allow`); a plain key allows them, so existing single-key bindings behave as before. `InputActions.bindings()` returns an `InputBindings` that saves and loads with kotlinx.serialization (`"type": "button"`/`"axis"` per action, `"type": "key"`/`"gamepad"` per chord), `rebind` and `rebindAll` change bindings while the game runs, keeping each action's trigger and toggle state, and `actionsBoundTo` says what a new chord would clash with. `ButtonBinding.describe()` gives each binding's modifiers and control, typed, for a label formatter. Controllers come in as `GamepadButton`, named by position, through `Input.setGamepadButton` and the snapshot's `gamepadButtonsDown`/`Pressed`/`Released`; no built-in host reads a controller yet. `ButtonAction` and `InputSnapshot` gained constructor parameters at the end, so code compiled against the old constructors must be recompiled.
