- **The build checks who owns each coroutine scope.** `./gradlew awakeVerify` runs the new `verifyCoroutineScopes`, which fails on a `CoroutineScope(...)` or `MainScope()` built in main code outside an approved owner (`AppCoroutineScope`, `SceneSession`, `core:state`'s store scopes, the `net:server-ktor` host) and on any `GlobalScope`. The sites that predate it are listed in `config/coroutine-scopes-baseline.txt`, which can only shrink. Detekt's `GlobalCoroutineUsage` and `SuspendFunSwallowedCancellation` are on; the second needs type resolution, which detekt 1.23.8 cannot do against Kotlin 2.4 classes, so it reports nothing until detekt is upgraded. `CoroutineScope.childScope(context)` and `AppServiceLookup.appChildScope(context)` in `awake:engine:platform` give code that is not an owner a scope under one. In a debug build a `FrameThreadGuard` (`awake:ecs`) makes `World`'s structural changes, `SceneAssetLibrary.requireMesh` / `requireMaterial` and `ScenePrewarm.close` throw off the frame thread the scene session recorded; it is on on the JVM with assertions on or `-Dawake.frameThreadChecks=true` and in debug Kotlin/Native binaries, does nothing on wasmJs, and costs one field read when off. "Coroutine scopes" in the app lifecycle guide lists the owners and the rules (#1321).
