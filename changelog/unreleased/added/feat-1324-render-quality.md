- **Session-scoped render quality with physical pixel budgets (#1324).** `RenderQuality` presets (`Auto`, `High`, `Balanced`, `Performance`) resolve through `RenderQualityPolicy` in `engine:render:contract` to a `Renderer.renderScale` from the presented surface's physical size, never `1 / devicePixelRatio`: `High` renders the full buffer, `Balanced` and `Performance` cap the short edge at 720 and 540 physical pixels, and `Auto` caps it by `GpuDeviceClass` (`Discrete` 1440, `Integrated` 1080, `Mobile` 900, `Software` 540, `Unknown` 1080), never upsampling. The budgets are overridable data (`RenderQualityBudgets`), and each preset also sets `Renderer.effectQuality` (`Auto` keeps the device's recommendation). It is opt in: call `renderQuality { persistence = ...; budgets = ...; initial = ... }` in `app { }` to register one `RenderQualitySettings` per app, which `GraphicsEngine` applies before every frame on every backend, scene or not; an app that never calls it renders exactly as before. `RenderQualitySettings.quality` is an observable `StateFlow` changed with `select`, saved through the app's `RenderQualityPersistence` callback, and scene overlays read it through `LocalRenderQuality`. A `launchWebGpuGame(..., renderScale = ...)` provider is now `GraphicsEngine.renderScaleOverride` and still wins over the setting's scale.
