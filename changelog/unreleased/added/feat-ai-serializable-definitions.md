- **Behaviour trees and state machines can be data.** `BehaviorTreeDefinition` and `StateMachineDefinition` in `awake:ai` are `@Serializable` documents a game authors as JSON, read with `AiDefinitionJson` (versioned, with `AiFormatMigration`s for older formats). Each node or state names a kind registered in an `AiRegistry`: an id, a typed `@Serializable` parameter class and a factory. `compileTree` and `compileStateMachine` check a whole definition and list every problem with where it is, such as an unknown kind (with the closest known one), a misspelt or missing parameter, the wrong number of children, or a transition with no trigger. Core registers `ai.sequence`, `ai.selector`, `ai.parallel`, `ai.inverter`, `ai.repeat`, `ai.cooldown`, `ai.timeout`, `ai.succeeder`, `ai.wait`, `ai.status`, `ai.compare`, `ai.has`, `ai.chance`, `ai.set`, `ai.copy`, `ai.remove`, `ai.add`, `ai.emit` and the state kind `ai.state`; a game adds its own with `register`, `action`, `condition` and `state`. A running `BehaviorTree`, an `AiStateMachine` and a `Blackboard` snapshot to data and restore exactly, a restored machine without entering its state again, and `ai.chance` draws from a per-tree seed, so runs repeat. Blackboard values are typed (`BlackboardValue`). For editors, `parameterSchema` describes each kind's parameters, `behaviorTreeNodeRegistry()` and `toNodeGraph()` bring trees into `awake:node-graph`, and `BehaviorTree.statusOf(path)` reports what each node returned on the latest tick. `BehaviorTreeSystem` and `AiStateMachineSystem` take an `AiEventSink` for emitted events, and `StateTransition` takes `afterSeconds`. `awake:ai` now depends on `awake:core:math`, `awake:core:schema` and `awake:node-graph` (#875).
