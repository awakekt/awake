- **A played project can check its assets against its asset lock as they load.** `loadProject(files.verifiedByAssetsLock())` reads the project's `assets.lock.json` and checks each asset it pins, by size and then SHA-256, as it's read, which catches a model, texture or scene modified, replaced or corrupted since the lock was written. A mismatch is logged and the asset still loads, unless the game handles `onMismatch` itself, such as telling its server, or passes `refuseMismatches = true`, when the read fails with an `AssetMismatchException`. An asset the lock doesn't pin loads unchecked, and so does a project with no lock, with a warning. The check costs one hash of each pinned asset, about 3 ms per MB on desktop.
  - `LockVerifiedAssetSource` is the check on its own, for any `AssetSource` and any `AwakeAssetsLock`. A lock read from the project's own files catches corruption and casual edits; a game that must catch deliberate ones gives it a lock built into its code.
