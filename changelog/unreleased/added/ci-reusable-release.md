- **One release workflow for every repository.** `.github/workflows/release-reusable.yml` runs the `release-cut` plugin's two-step release for any Gradle repository: a dispatch cuts the release and opens the `chore(release): cut <tag>` PR, and merging it tags the squash commit by its full SHA. It takes `channel`, `bump`, `runs-on` (JSON labels, for self-hosted runners), `java-version`, `version-property`, `version-files`, `gradle-args`, `milestone` and `dry-run`, refuses while another cut is open, and explains a missing or under-scoped `RELEASE_TOKEN` (Contents, Pull requests and Workflows) without printing it. Core's own Release workflow now calls it; `docs/templates/release.yml` is the caller to copy, and `docs/release-process.md` shows how to adopt it.
- **`releaseCut` can take the version from a file and skip the local tag.** For a repository that keeps its version in files, three optional properties, all off by default: `-Prelease.versionProperty=<key>` counts on from that key in the root `gradle.properties` instead of the newest tag and writes the new version back; `-Prelease.versionFiles=<a,b>` also rewrites each listed file's first JSON `"version"` member or `version =` line, e.g. `awake.project.json`; and `-Prelease.tag=false` commits without tagging, for a workflow that tags the squash commit after review. With none of them a cut behaves as before.
