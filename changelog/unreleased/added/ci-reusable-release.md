- **One release workflow for every repository.** `.github/workflows/release-reusable.yml` runs the `release-cut` plugin's two-step release for any Gradle repository: a dispatch cuts the release and opens the `chore(release): cut <tag>` PR, and merging it tags the squash commit by its full SHA. It takes `channel`, `bump`, `runs-on` (JSON labels, for self-hosted runners), `java-version`, `version-key`, `version-file`, `sync-version-files`, `gradle-args`, `milestone` and `dry-run`, refuses while another cut is open, and explains a missing or under-scoped `RELEASE_TOKEN` (Contents, Pull requests and Workflows) without printing it. Core's own Release workflow now calls it; `docs/templates/release.yml` is the caller to copy, and `docs/release-process.md` shows how to adopt it.
- **`releaseCut` serves a repository that keeps its version in files.** A missing `CHANGELOG.md` is created, and one without `## [Unreleased]` gets the section. Optional properties, all off by default: `-Prelease.versionKey=<key>` (in `-Prelease.versionFile`, default `gradle.properties`) counts on from that version instead of the newest tag and writes the new one back; `-Prelease.syncVersionFiles=<a,b>` also rewrites each listed file's first JSON `"version"` member or `version =` line, e.g. `awake.project.json`; `-Prelease.tag=false` commits without tagging, for a workflow that tags the squash commit after review; and `-Prelease.git=false` only edits files. With none of them a cut behaves as before.
