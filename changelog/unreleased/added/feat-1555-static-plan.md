- **A still 3D scene is planned once on WebGPU.** When the camera, light and environment held and nothing a frame's draws read changed (meshes, materials, placement, the clocks their shaders read), the scene compiler hands back the last frame's pass input without folding, preparing or sorting anything; the second still frame after the camera stops is the first handed back. A backend opts in with `GpuDrawPreparer.redrawsPreparedFrames`; WebGPU does. Vulkan, whose prepared frames bind per-frame-in-flight storage, keeps planning every frame, and `RenderSystem3D`'s non-realtime path no longer redraws its last plan there, which let a later frame's preparation rewrite storage a reused frame still in flight was reading. The planner now also forwards `clampsShadowDepth`, so a device that clamps shadow depth keeps its cascades' fitted near planes rather than pulling them back to tall casters: finer shadow depth on those frames, nothing else visible (#1555, #1452).
