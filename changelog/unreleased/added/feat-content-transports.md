- **Ready-made content transports, and protected content that waits out a 429.** Two optional modules hold a `ContentTransport` each, so a game takes only the HTTP stack it uses and `com.awakekt.awake:project` still carries none: `com.awakekt.awake.project:transport-ktor`'s `KtorContentTransport(client, baseUrl)` sends through the game's own Ktor `HttpClient` (the game picks the engine) on desktop, Android, iOS and the web, and `com.awakekt.awake.project:transport-browser`'s `BrowserContentTransport(baseUrl)` calls the browser's `fetch()` on wasmJs with no HTTP library, aborting the request when the fetch is cancelled and naming in its error what a cross-origin server's CORS answers must allow. Both resolve relative index URLs against `baseUrl`, send the token's `Authorization` header and a bundle member's `Range` header, and answer every status with the response headers. `TokenAuthorizedFetch` now waits out a 429 Too Many Requests and sends the request again, as the new `RateLimitBackoff` says: exactly as long as `Retry-After` asks, in seconds or as an HTTP date, otherwise a jittered exponential delay (up to 1 s, doubling, capped at 8 s), for at most 4 sends of a request and 30 s of waiting per fetch by default, then a `ContentFetchException` with status 429 that says why it stopped; waits suspend and never block, the token is checked again after each, and `RateLimitBackoff.None` turns it off. Content bundles, whole or one member at a time, go through the same path. `ContentResponse` gains `headers` and a case-insensitive `header(name)` (its two-argument constructor is kept), and `TokenAuthorizedFetch`'s constructor gains an optional `rateLimitBackoff` before `tokenProvider`, which changes its JVM signature. The Protected content guide shows both transports, the CORS headers a content server must send, and the backoff policy (#1036).
