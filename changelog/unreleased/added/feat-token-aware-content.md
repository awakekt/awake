- **Protected content loads with a short-lived read token.** `TokenAuthorizedFetch` wraps the host's HTTP client, behind the new `ContentTransport`, with a token provider the game supplies (`suspend () -> ReadToken`, the token and how long it stays valid). It attaches the token to the index and every file request, as an `Authorization: Bearer` header or, for a host that loads through a URL alone, a query parameter (`ReadTokenPlacement.QueryParameter`, `access_token` by default); asks for the next token shortly before the current one expires; and on a 401 or 403 refreshes once and retries that request, throwing `ContentFetchException` with the status if the fresh token is refused too. Requests running at once, such as `IndexedAssetSource.prefetch`'s, share one refresh. The token never appears in an exception message, a printed `ReadToken` or `ContentRequest`, or a `ContentCache` key or value, so the cache stays keyed by SHA-256 and a new token or release finds the files it already has. The new `IndexedAssetSource.open(indexPath, fetch: TokenAuthorizedFetch, ...)` reads the index through the same path; existing `IndexedAssetSource(index, fetch, cache)` callers are unchanged. The Protected content guide shows a game wiring its token provider (#1031).
