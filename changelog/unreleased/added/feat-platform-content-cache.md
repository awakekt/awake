- **A default content cache per platform.** `platformContentCache(namespace)` answers the `ContentCache` to pass to `IndexedAssetSource.open`, so a second run reads unchanged files instead of downloading them: `IndexedDbContentCache` in a browser, and a `FileSystemContentCache` in `<namespace>/awake-content` under the user's cache folder on desktop (`$XDG_CACHE_HOME` or `~/.cache` on Linux, `~/Library/Caches` on macOS, `%LOCALAPPDATA%` on Windows) and the app's `Library/Caches` on iOS. Android code passes the app's `Context.cacheDir` with `platformContentCache(namespace, cacheDir)`, since `awake:project` reaches no `Context`; the one-argument call answers null there. The caller names the cache: `namespace` is one folder name (letters, digits, `.`, `_`, `-`), checked before any storage is touched. Storage the platform blocks or fills still falls back to the network, and a cache folder that can't be created gives null, which means no cache. The Protected content guide shows the setup (#1140).
