- **A browser game's socket runs in a Web Worker, so a busy frame no longer delays it.** The new `awake:net:client-browser` module's `connectBrowserSocket(url)` (wasmJs) opens the browser's own `WebSocket` in a dedicated worker (`awake-net/socket-worker.js`), which stamps each message as it arrives, sends what the page posts at once and reports `bufferedAmount` from the socket's own thread. It returns a `BrowserSocketTransport`, a `DirectTransport` (new in `awake:net:api`) whose `arrivalLag` takes the time a packet waited for the page out of ping timing and whose `bufferedBytes` never reads less than the socket holds, with the close code and reason. It falls back to a socket on the page when the browser has no `Worker` or the script doesn't load, and `BrowserSocketMode` picks either; the new `com.awakekt.awake.plugin.socket-worker` Gradle plugin puts the script beside a web app's page. The Ktor server transport needs no change (#1280).
