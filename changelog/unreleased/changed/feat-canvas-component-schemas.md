- **Canvas elements are saved as focused components.** A scene or prefab now saves a canvas element as `canvas_rect`, and the `canvas_text`, `canvas_appearance`, `canvas_layout`, `canvas_cluster`, `canvas_bind`, `canvas_follow`, `canvas_follow_arrow`, `canvas_input`, `canvas_tooltip` and widget component (`canvas_button`, `canvas_bar`, `canvas_sweep`, `canvas_stepper`, `canvas_joystick`, `canvas_look_area`, `canvas_text_field`, `canvas_view` or `canvas_image`) it needs, each loaded by its own binding, generated with `@SceneBinding` and listed in the module's `CanvasSceneComponents` registry, which `DefaultSceneComponentResolvers` now registers in place of its hand-kept canvas list; `canvas_scaler`, `canvas_controls`, `canvas_follow_limit` and `canvas_follow_occlusion` are generated too, and save byte for byte as before. A node lists its canvas components in binding-name order. Files saved with the single `canvas_element` still load and draw unchanged, read as the same component set, and save in the new form; a field a kind never used, such as a Panel's `text`, is dropped. The ECS holds each component on the element's entity, with a runtime-only `CanvasPointerState` for what the player is doing, so a system can query `family<CanvasButtonWidget, CanvasPointerState>()`; `World.syncCanvasElements()` keeps the entity's components and its `CanvasElement` in step, and `SceneCanvas` calls it each frame, as `SceneLoader.fromWorld` does before it saves. Typed canvas parts expose their components (`rect`, `pointer`, a widget part's `widget`, a Text part's `words`). `SceneDocument.withCanvasComponents()` rewrites an older file, and `SceneNode.canvasElementView()` reads a node in either form (#1088, #1104).
