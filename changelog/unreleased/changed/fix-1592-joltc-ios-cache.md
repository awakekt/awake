- The iOS native action caches the JoltC and JoltPhysics static libraries, as it already caches MoltenVK (#1592). The cache key is the JoltC submodule commit plus the build script and CMake helper that configure it. The device and simulator slices are cached apart, each under a key and path naming only its own slice, so a restore cannot put one where the other's link reads it. On a hit the CMake build is skipped for that slice, and only the slices that missed are built. Hit or miss, every library is checked: present, non-empty and arm64. Where its objects name a Mach-O platform, it must be its slice's. Only a verified build is saved. On v0.54.0 the build took 1 min 46 s in Consumer and ran again in Release. `scripts/ios-native-cache.test.sh` holds the order, and the separation of the slices, in CI's Release scripts job.
