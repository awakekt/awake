- **Per-frame UI staging and index-byte allocation reuse their buffers instead of churning them.** The 2D coalescer (`render:passes2d`) now takes an optional renderer-owned `DynamicRunArrayPool` and stages a UI run whose contents change every frame into reused ping-pong `FloatArray`/`IntArray` buffers rather than allocating a fresh pair per run per frame -- a steady full-HUD-like scene with 22 moving meshes dropped from ~700 KB/frame of staging garbage to ~2 KB/frame on a desktop `ThreadMXBean` probe. The pool's generation flip guarantees a changing run is still handed a different array instance than last frame, so both backends' `DynamicMesh` identity-skip keeps re-uploading it correctly while an unchanged run still skips through `RetainedDrawRunCache`; retained runs keep their own immutable arrays and never pass through the pool. `IntArray.toByteArrayLE(into)` adds an in-place variant (`core:geometry`) and the Vulkan `ui.DynamicMesh` keeps one reused index-byte buffer per frame slot instead of allocating a `ByteArray` per upload. `UniformWriter.reset()` (`render:contract`) lets a caller keep one writer per layout and refill it each draw. All additions are additive and binary-compatible (#1224).
