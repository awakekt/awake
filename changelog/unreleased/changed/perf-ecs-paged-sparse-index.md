- **ECS sparse indexes hold only the pages their entities fall in.** Every component set and query family kept one `int` array sized to the highest entity id it had held, mostly empty: 13 MiB of live heap in a populated scene a consumer measured on its way to Android's heap limit (#1753). The index now makes pages of 64 ids the first time one of their ids is set, so a set of 160 entities in a 16,384-entity world holds 2.7 KiB rather than 64 KiB, or about 34 KiB when its entities are scattered across the world. Looking an entity up reads one more array and still allocates nothing.
