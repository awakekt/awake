- **Textures on the web can go straight from the browser's decode to the GPU.** `decodeBrowserImage` (`awake:core:image`, wasm) keeps the browser's decoded `ImageBitmap` and reads nothing back. `GpuDevice.createImageMaterial` uploads one through the new optional `GpuImageUpload` capability: WebGPU in a browser copies it with `copyExternalImageToTexture` and draws `Linear` mips on the GPU, so no pixel crosses into wasm (#1184). Any other device, or a browser without the API, reads the pixels on the CPU as before. A mipmapped 1024×1024 texture now holds headless Chromium's main thread for about 16–19 ms, decode and upload together, where decoding with `createBitmap` and uploading a `TextureAsset` took about 240 ms on the same machine. Orientation, straight alpha, colour and the `RGBA8Unorm` format are unchanged, and mips are within rounding of the CPU chain. WebGPU textures are now created with `CopySrc` usage, so they can be read back.
