- **A component type's id is found without hashing its class (#1428).** Each component class now has a process-wide index, and each world keeps its type ids in an array at that index. On the JVM a reified `world.get<T>`, `has`, `remove` and `family` read the index from a `ClassValue` instead of hashing the class into a map, with no change to their compiled signatures. The new `ComponentType<T>` handle (`componentType<T>()`), with `world.get(entity, handle)`, `has`, `add`, `remove` and `family`, carries its index on every platform, so hot paths on Android, Kotlin/Native and Kotlin/Wasm skip the lookup too. One handle serves every world and survives `World.clear`.
