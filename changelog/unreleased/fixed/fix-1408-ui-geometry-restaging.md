- **UI meshes that stop changing stop being restaged and re-uploaded every frame (#1408).** A cacheable span that missed the retained draw-run cache after its first sight went through the staging-array pool, and a pooled span was never stored, so a name plate or HUD mesh that moved once and then stood still was restaged and force-uploaded every frame from then on. A pooled span whose content repeats from the previous frame is now staged into immutable arrays once and stored, so it hits the cache and skips its upload; a span that changes every frame stays pooled, and nothing is promoted when a frame has more spans than the cache holds. On WebGPU a UI mesh upload no longer slices a new `ArrayBuffer` out of wasm linear memory per array: the web writes from a view of linear memory, and the JVM through a kept native buffer.
