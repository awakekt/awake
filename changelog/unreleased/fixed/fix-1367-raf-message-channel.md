- **The web page keeps receiving a worker's messages while a key is held on a slow frame (#1367).** `runBrowserCanvas` used to do each frame's work inside the `requestAnimationFrame` callback. Once a frame took longer than the gap between two key repeats (about 33 ms), a held key starved the socket worker's messages to the page, so a ping reading climbed about a second per second and no server messages arrived. Each frame callback now asks for the next one first and posts the frame's work as a `MessageChannel` task, skipping a frame while the last one's work hasn't run, so the worker's messages take their turn. Frame timing still follows the display.
