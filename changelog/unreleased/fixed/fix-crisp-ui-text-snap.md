- **Small UI text lands on the pixel grid.** Each text line's start and baseline now snap to whole device pixels, so a stem or a flat glyph bottom is one solid pixel row or column instead of two grey ones, and a line box's leftover height no longer changes how the same text renders. Glyph advances stay fractional within the line, and text under a scale transform keeps sub-pixel positions so animated text still moves smoothly (`DrawScope.isDevicePixelAligned` says which). The em is a whole number of device pixels: at 125% and 150% display scale `13.sp` is 16 and 20 pixels rather than 16.25 and 19.5, and measuring and painting read the same rounded size. On Vulkan, `HHHH` at 12sp used to end on a row peaking at 215 to 230 of 255 with up to 188 on the row below, depending on the line height; it is now 255 and 0 for every line height. The software-rasterizer baselines that contain text moved by at most a pixel.
