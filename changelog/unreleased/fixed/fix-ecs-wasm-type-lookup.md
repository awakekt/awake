- On Kotlin/Wasm, a reified `World.get`, `has` or family lookup no longer allocates a type key or goes through a generic hash map per call. The world keeps component type IDs in an open-addressing table keyed by the class itself and hashed by its simple name; two classes with the same simple name are told apart by comparing the classes. Code inlined from earlier releases, which passed a wrapper key, still resolves. On the JVM a reified get allocates nothing (measured 0 bytes). `ComponentType` handles remain the cheapest form for per-entity hot paths on every platform.
