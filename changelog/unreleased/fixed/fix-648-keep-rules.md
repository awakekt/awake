- **An app that shrinks and obfuscates its release keeps what Awake's native code finds by name.** A shader that fails to compile in a shrunk Android build now throws `NagaException`, as it does unshrunk, rather than a `NoClassDefFoundError`, because the shader compiler's rules keep the exception Naga's Rust throws by name. The desktop window, `awake:engine:window`, ships rules for the first time, so a ProGuard'd desktop build can still link `GlfwWindow`'s native functions. Every module with native code now ships its rules in its desktop jar too, under `META-INF/proguard/`, where R8 looks for a library's rules, as well as in its Android library. `./gradlew verifyKeepRules`, part of `awakeVerify`, fails when a module's C, C++ or Rust names a class, or binds a native method, that no rule in its `consumer-rules.pro` keeps.
