- **A malformed glTF or GLB file fails promptly with one typed error instead of hanging, exhausting memory or throwing whatever broke first.** `GltfParser` trusted the counts, lengths and indices a file declared: a GLB chunk length of `0xFFFFFFF8` looped forever, an accessor `count` allocated its array before anything checked the buffer could hold it, and a bad buffer, bufferView, accessor, node or skin reference threw `IndexOutOfBoundsException` partway through an import. Every parse now checks the GLB header and chunk lengths and alignment, the JSON size, buffer and bufferView ranges, accessor count × stride × size against the bytes present in overflow-safe arithmetic, index values against the vertex count, sparse substitutions, base64 payloads, inverse bind matrix and keyframe counts, and the node hierarchy for out-of-range children, shared parents, cycles and depth, before it allocates or reads. Any failure throws `GltfFormatException`, an `IllegalArgumentException` whose `location` names where in the file the problem is (`accessors[3].count`, `glb.chunks[1].length`, `nodes[7].children[0]`). The parse functions take `GltfLimits` to bound JSON size, accessor count, total decoded bytes and node depth, and read sparse accessors, which they used to reject or ignore.
