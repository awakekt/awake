- **A host with no renderer no longer decodes the scene UI's images.** `loadProject` decoded every image a `canvas_element` names, such as an item icon sheet of 2048 by 1856 pixels, which is 15 MB decoded, even on a game server that draws nothing. `loadProject(files, hasRenderer = false)` now only reads them, to check that their paths resolve, and logs one it cannot read as a drawn host does, so no `CoreSceneContent.CanvasImages` are loaded. `loadSceneContent` and `loadCapabilityContent` take the same `hasRenderer`, and a capability reads it as `SceneContent.Builder.hasRenderer` to skip what only drawing needs. A project loaded that way and then played by `runProject` draws its canvas without its images. Particle sprites and shader effects still load as before.
  - `checkCanvasImages(document, assets)` in `awake:scene:canvas` is the check on its own: it reads each image once, decodes none, and returns the paths it could not read.
  - `hasRenderer` comes before `physicsWorld` in `loadProject`, which stays last so a trailing lambda still makes the physics world. A call that passed `physicsWorld` as its third positional argument names it now.
