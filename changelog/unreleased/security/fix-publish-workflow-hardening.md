- **The publish workflow refuses unexpected refs, runs with a read-only token and pins its actions.** A first job checks the ref before any other starts: only `main`, `release/**`, and `v*` / `vulkan-v*` tags made of `[0-9A-Za-z.+-]` publish, and every script reads the ref through `env:` rather than as `${{ }}`, so a tag name is never shell syntax. A Core release must also tag a commit on `main` or a `release/**` branch. The default token is `contents: read`; only the two jobs that create GitHub releases get `contents: write`. The Maven Central and signing secrets sit on the one step that uses each, not on the job, and every third-party action is pinned to a full commit SHA, moved by Dependabot. `scripts/central-upload.sh` asks Central whether a bundle's version is already published and uploads nothing if it is, so a re-run cannot send a release twice.
