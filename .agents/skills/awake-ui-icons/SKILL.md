# Icon Authoring in Awake

One hard rule, one tool, one layering scheme.

## The Rule: Never Hand-Write Path Coordinates

All `ImageVector` path data is generated by `.agents/skills/awake-ui-icons/scripts/svg_to_ui_image_vector.py` from an
official SVG source. No hand-transcription, no hand-editing generated output, no deriving one
icon from another by rotating/mirroring coordinates.

This encodes a real shipped bug (found in the 2026-08-08 pixel-accuracy audit): the original
`HeroIcons.kt` was transcribed by hand with every corner arc "collapsed to its straight-line
endpoints", then `chevronRight`/`chevronLeft` were derived by rotating the already-approximated
`chevronDown` -- replicating the error 4x and landing coordinates off any pixel grid. The result
was an icon set with zero curve segments in it, reported by users as "not pixel perfect,
smoothness, curves".

Hand-derivation always looks safe at the time ("the arcs round under a pixel"). It is how curve
data silently disappears. The generator preserves curves exactly; use it even for shapes that
look like they need no curves.

## Workflow: Adding A Heroicon

`HeroIcons.kt` is **generated at build time** and is not in `src/`. Do not look for it to paste
into -- vendor the SVG instead and let the build produce the Kotlin.

1. Copy the official SVG out of the pinned release into the matching tier directory:

   ```bash
   cp <heroicons>/optimized/20/solid/<name>.svg awake/heroicons/src/commonMain/svg/heroicons/20-solid/
   ```

   The pinned version lives in `awake/heroicons/src/commonMain/svg/heroicons/manifest.json`
   (`v2.2.0` today, with the tarball's SHA-256). Take the SVG from **that** release, not from
   `master`, or the vendored set stops being one coherent version.

   **Match the tier to the ones already around it.** Heroicons draws 20/solid for 20px and 24/solid
   for 24px, with different stroke weights and detail, so an icon borrowed from the other tier looks
   heavier or lighter than its neighbours in the same control. `Solid24` holds eight stack-shaped
   icons and nothing else; reach for `Solid20Mini` unless a glyph genuinely only exists at 24.

2. Build. The Kotlin `val` appears automatically -- the name is the filename in camelCase, so
   `arrow-down-tray.svg` becomes `arrowDownTray`:

   ```bash
   ./gradlew :awake:heroicons:generateImageVectors
   ```

3. Run `./gradlew :awake:heroicons:desktopApiCheck` and dump if it fails; a new icon is new public
   API.

4. If a shadcn component needs it, add a pointer in `ShadcnIcons` (designsystem), not a copy.

### How The Generation Works

`awake.icon-codegen-convention` runs the generator once for the whole set and registers
`build/generated/imagevector` as a `commonMain` source directory. Two things there are load-bearing
and easy to get wrong:

- It registers the **task**, not the directory. `kotlin.srcDir(<directory>)` compiles fine and
  silently never runs the generator, so a clean checkout builds a module with zero sources and every
  consumer fails to resolve `HeroIcons`.
- Output goes to `build/generated`, never `src/`. detekt and spotless are both scoped to `src/**`,
  so nothing has to exclude the generated tree, and Gradle can infer the compile dependency instead
  of needing the `dependsOn`/`mustRunAfter` web that `awake.shader-pipeline-convention` carries
  because it writes into `src/`.

Python is a build requirement for this module. Point `awake.icons.python` or `AWAKE_PYTHON` at an
interpreter on a host where `python3` is not on PATH.

### Generating Outside The Build

For a one-off, or for a pack with no manifest:

```bash
# one icon
python3 .agents/skills/awake-ui-icons/scripts/svg_to_ui_image_vector.py icon.svg --name chevronDown

# a whole directory, one process -- 20 icons take 3.6s as separate processes and 0.3s batched
python3 .agents/skills/awake-ui-icons/scripts/svg_to_ui_image_vector.py \
    --batch <dir>/*.svg --dp 24 --source-template "Heroicons \`{stem}\` (24/outline)"

# the whole file, exactly as the Gradle task produces it
python3 .agents/skills/awake-ui-icons/scripts/svg_to_ui_image_vector.py \
    --manifest awake/heroicons/src/commonMain/svg/heroicons/manifest.json
```

Add `--packed` to emit `packedImageVector("…")` string constants instead of builder calls (see
`PackedImageVector.kt`). Lucide is still hand-pasted: those icons went through `picosvg` stroke
expansion, which is a second external toolchain, and there are eight of them.

Verify with the generator's own check once after any script change:

```bash
python3 .agents/skills/awake-ui-icons/scripts/svg_to_ui_image_vector.py --self-test
```

## What The Generator Guarantees

- Full SVG path grammar (M/L/H/V/C/S/Q/T/A/Z, absolute+relative, implicit repetition,
  concatenated arc flags like `a.75.75 0 011.06.02`).
- Arcs become cubic Beziers (W3C endpoint-to-center parameterization, <=90-degree segments,
  exact endpoints) -- curves are preserved, never flattened to line segments.
- Holes are preserved: `fill-rule="evenodd"` with NESTED subpaths (Heroicons' clock/camera
  style) emits `path(fillRule = UiFillRule.EvenOdd)`, which the engine tessellates via
  containment-based hole grouping + scanline fill (`resolveFillGroups`/
  `scanlineFillTriangulation` in ui-core `UiPath.kt`).
- Deterministic output: same SVG in, same Kotlin out (4-decimal rounding, trimmed zeros).
- Refuses what the engine can't render instead of silently approximating: unsupported `transform`
  attributes, non-path shape elements, and evenodd
  subpaths that CROSS rather than nest (not representable by containment grouping).

## Engine Limits To Know Before Blaming The Data

- **Stroke paths are supported.** The generator carries SVG stroke width, cap, and join into
  `UiStroke`, while `shadcnIcon` renders it through `DrawScope.drawStrokedPath`. Preserve the
  exact source data rather than converting a stroke into approximate fill paths.
- **Concave fills and holes are handled by the tessellator** (`tessellateFill`/
  `tessellateFillAa`, ui-core `UiPath.kt`): convex hole-less contours centroid-fan (the hot
  path); everything else -- concave contours, nested holes -- goes through scanline-trapezoid
  fill. If a glyph renders wrong, suspect the tessellation or the consuming rasterizer --
  never compensate by editing path data. (Both bugs of that class shipped once: a convex-only
  centroid fan blunting chevrons, and a CPU-rasterizer bbox truncation banding hole glyphs.)
- **Sizing:** `viewportWidth/Height` must equal the source SVG's viewBox (20 for the mini tier).
  `defaultWidth/Height` is per-tier and currently read by nothing -- `fitTo` scales from the
  viewport to the slot, so the intrinsic size never participates. Before relying on it, check
  whether anything consumes it; the committed set had drifted to two values inside one tier without
  any visible effect, which is what a field nobody reads looks like.

## Tier And Registry Layering

- `HeroIcons` (`ui-headless`): raw generated vector data, nested one object per real Heroicons
  tier (`Solid20Mini`, ...). Tiers ship different path data -- never rescale one tier to fake
  another. Add a tier object only when an icon actually needs it.
- `UiIcons` (`ui-headless`): the registry headless widgets read.
- `ShadcnIcons` (`ui-designsystem`): overridable `var` pointers defaulting to `HeroIcons` --
  the brand seam. Callers swap icon sets here, never by editing `HeroIcons`.

Icons from other libraries (Lucide, brand glyphs) follow the same pipeline: official SVG in,
generator out, new unbranded registry object alongside `HeroIcons` if the set is real.

## Source-Faithful Defaults

`HeroIcons` is Awake's current *fallback registry*, not a claim that every upstream design uses
Heroicons. A recipe must choose its default glyph family from the visual source it is matching:

- For a generic Awake/headless control with no external visual source, use the `UiIcons` default,
  which currently delegates to Heroicons.
- For shadcn parity, inspect the pinned shadcn source first. Its current recipes import Lucide, so
  a visibly compared Lucide glyph needs generated Lucide data and a `ShadcnIcons` pointer; do not
  silently substitute a similarly named Heroicon merely because it already exists.
- Keep the recipe dependent on `ShadcnIcons`, never directly on `HeroIcons`, when the icon is
  branded or source-specific. That preserves the skin override seam and lets the reference family
  change without rewriting component layout.

Stroke-only SVGs are supported through `UiStroke`; generate the exact source data. Only an SVG
feature unsupported by the generator or rendering pipeline (for example an unhandled transform or
non-path shape after preprocessing) qualifies as an engine capability finding, with source and
rendered evidence in the parity core-issue tracker.
